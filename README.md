# Linkex JD2

<img src="public/icons/icon-128.png" alt="" width="64" height="64" align="right" />

[Linkex](https://www.linkex.io/) の共有ファイルを、[JDownloader 2](https://jdownloader.org/)（JD2）でまとめて落とすEdge拡張機能。共有リンクを登録しておけば、共有からダウンロードURLを発行してJD2に渡し、完了まで見届ける（直接取れないファイルは、自分のストレージに保存 → JD2でダウンロード → 完全削除、の流れで取る）。

> v1 までは「Linkex Motrix」として、Motrix（aria2 RPC）へ渡していました。v2 で JD2 専用に変えています。Motrix に渡し済みだった件は、更新したときに「完了（Motrix版で渡した分）」として扱います（Motrix の中では最後まで続きます）。

> [!IMPORTANT]
> これはLinkex（LINKINFLU PTE. LTD.）の公式ツールではなく、関係もありません。個人利用の範囲で、Linkexの利用規約を守って使ってください。Linkex側の仕様が変わると動かなくなることがあります。利用は自己責任でお願いします。

## 必要なもの

- Microsoft Edge（Chromium版。Chromeでもおそらく動くが未確認）
- [JDownloader 2](https://jdownloader.org/)。「設定 → 詳細設定」で `RemoteAPI: Deprecated Api Enabled` をオンにして再起動しておく（この拡張機能は 127.0.0.1:3128 のローカルAPIで追加・完了確認・速度表示をする。このAPIはこのPCの中からしか使えず、パスワードはない）
- Linkexのアカウント（共有ファイルは自分のストレージに保存しないと落とせないため、ログインが必要）
- ビルドする場合は Node.js 22.18 以上（テストが `.ts` をそのまま Node で動かすため。`package.json` の `engines` にも書いてある）

## 入れ方

### ビルド済みのものを使う（かんたん）

1. [Releases](https://github.com/Hoyomaru/linkex-jd2/releases/latest) から `linkex-jd2-vX.Y.Z.zip` をダウンロードし、好きな場所に展開する（このフォルダは消さずに置いておく）
2. `edge://extensions` を開き、左下の「開発者モード」をオンにする
3. 「展開して読み込み」で、展開したフォルダ（`manifest.json` が入っているフォルダ）を選ぶ

新しい版にするときは、フォルダの中身を入れ替えてから、拡張機能の一覧で「再読み込み」を押す。キューや設定は残る。

### 自分でビルドする

```
npm install
npm run build
```

`npm run build` は型チェック（`tsc --noEmit`）もしてからビルドする。型チェックだけなら `npm run typecheck`（テストのコードも `tsconfig.test.json` で型チェックする）、テストは `npm test`。

`dist/` に拡張機能ができるので、上の手順3で `dist` フォルダを選ぶ（`content.js` だけは別の設定 `vite.content.config.ts` で1ファイルにまとめてビルドする）。ビルドし直したら、拡張機能の一覧で「再読み込み」を押し、開いている共有ページも再読み込みする。`npm run watch` にしておくと、ソースを変えるたびに `dist` が作り直される（このときも「再読み込み」は必要）。

## 使い方

1. ツールバーのアイコン →「専用ページを開く」
2. 設定にJD2の接続先（ふつうは初期値のまま）と保存先を入れて「保存」→「接続テスト」
3. キューに共有リンクを登録する（どちらでも）
   - 専用ページの「キュー」欄に共有URLを1行に1つずつ貼って「キューに追加」
   - Linkexの共有ページ右下のパネルで「全部キューに追加」または「選んで追加」（「選んで追加」は検索欄でファイル名・フォルダ名から絞り込める。絞り込み中は表示中のファイルだけが追加の対象）
   - ポップアップに貼り付けるか、「このページのリンクを集める」で今のページの共有リンクをまとめて拾う
   - Linkexのリンクを右クリック →「Linkex JD2 のキューに追加」（文字を選んで右クリックすると、その中のリンクを全部追加）
4. 「開始」を押す。次のときは、追加すると自動で始まる
   - ポップアップ・専用ページ・共有ページのパネルから追加したとき：その画面の「追加したら開始する」がオン（初期値）
   - 右クリックで追加したとき：設定の「右クリックで追加したらすぐ開始」がオン（初期値）

ポップアップと専用ページには「見積もり」として、これから落とす合計サイズと、今の転送量の残りで足りるか（足りなければ上限ごとに止まりながら何日かかるか）が出る。共有ページの「選んで追加」でも、共有全体のサイズが分かる。

ツールバーのアイコンには残りの件数が出る（失敗があれば赤）。すべて終わったときや、JD2につながらない・Linkexのログインが切れたなどで止まったときは、Windowsの通知で知らせる。

Linkexにはログインしておくこと。処理中はLinkexのドライブが固定タブで自動的に開く（裏にあってよい）。

### 設定

| 項目 | 初期値 | 内容 |
|---|---|---|
| JD2の接続先 | `http://127.0.0.1:3128` | JD2のローカルAPI（Deprecated Api） |
| 基準フォルダ | 空（JD2の既定） | この下に `共有名\共有内のフォルダ` を作る。共有の中身がフォルダ1つだけなら、共有名の段を飛ばしてそのフォルダから作る |
| APIを呼ぶ間隔 | 300ミリ秒 | 一時的な速度制限を避けるため |
| JD2に渡しておく数 | 3（1〜16） | ダウンロードURLには期限があるので、JD2の中で長く待たせないよう、渡すのはこの数まで。実際に同時に落とす数はJD2の設定（全体の同時ダウンロード数・同じホストからの同時ダウンロード数）に従う。Linkexのファイルはすべて同じCDNから来るので、JD2の「同じホストからの同時ダウンロード数」が1だと1件ずつになる（「接続テスト」でJD2の今の設定が出る） |
| 強制ダウンロード開始 | オフ | オンにすると、JD2に渡した件をJD2の「強制ダウンロード開始」にする。JD2の同時ダウンロード数・同じホストからの数の設定を超えて、「JD2に渡しておく数」まで同時に落とす。JD2をほかの用途と共用していて、JD2の設定は変えずにこちらだけ増やしたいとき向け。強制で動いている分もJD2の同時数に数えられるので、その間はほかの用途の分が待たされることがある |
| 同時に処理する数 | 3（1〜6） | Linkex側の処理を同時に進める数（1にすると1件ずつ）。LinkexのAPIを同時に呼ぶ数の上限も兼ねる。保存せずに取るときは、URLの発行を同時に進める数になる。保存してから取るときは保存〜削除を同時に進める数で、保存中のコピーの合計は5GBと空き容量の小さいほうまで。同じ名前のファイルは同時に保存しない |
| 保存せずにダウンロード | オン | 共有のファイルを自分のストレージに保存せず、共有から直接ダウンロードURLを発行してJD2へ渡す（Linkexへの呼び出しが1件あたり1回で済み、容量も使わない）。直接取れなかった件だけ、下の「処理の流れ」のとおり保存してから取る |
| 先に保存しておく数 | 1（0〜3） | 保存してから取る件にだけ使う（「保存せずにダウンロード」がオンなら、直接取れなかった件だけが対象）。JD2に渡しておく数が埋まっている間に、次の件の保存まで済ませておく数（先読み）。JD2に空きができたら、すぐURLを発行して渡す。URLは渡す直前に発行するので期限は気にしなくてよい。0にすると、空きができてから保存を始める |
| 転送量の上限で一時停止 | オン | 公式Web版と同じ動き。転送量は1分に1回まで確かめ、その間は残りから始めた件のサイズを引いて見込む。オフにすると転送量の表示に関係なく処理を続け、確認も省く |
| 残ったファイルを片付ける | オフ | オンにすると、Linkex側で処理中の件がないとき（10分に1回まで、容量が足りないと言われたらすぐ）に、自分のストレージのルートとゴミ箱に残ったファイルを完全削除する。時間切れの後に遅れてできたコピーや、削除の途中で止まったコピーで容量が埋まるのを防ぐ。**保存前からあったファイルも消える**（フォルダとキューの件のコピーは消さない）ので、自分のファイルを置いていないときだけオンにする |
| 通知を出す | オン | すべて終わったとき・止まったとき |
| 右クリックで追加したらすぐ開始 | オン | 右クリックメニューから追加したときの動き |

保存先にもう同じ名前のファイルがあると、JD2の初期設定では上書きするか聞いてきて、そのダウンロードは答えるまで止まる。留守中に回すなら、JD2の「設定 → 一般 → ファイルが既に存在する場合」を、聞かずに済む動きにしておく。おすすめは「名前を変える」。「スキップ」にすると、スキップされた件はJD2で無効・スキップにされた件として、キューに「ダウンロード中」のまま残り、メモを付けて待つ（JD2で有効に戻すか、キューから外す）。

## 処理の流れ（1件ごと）

「保存せずにダウンロード」がオン（初期値）なら、同じ中身をダウンロード済みでないかを確かめた後、共有から直接ダウンロードURLを発行してJD2へ渡し、JD2での完了を見届ける（下の 4 と 6 だけ）。直接取れなかった件と、オフのときは次のとおり。

1. 同じ中身をダウンロード済みなら飛ばす（ハッシュで判定。「もう一度ダウンロード」で強制できる。記録は専用ページの設定にある「ダウンロード済みの記録」でまとめて消せる）
2. 保存前の自分のファイル一覧を記録 → 共有から保存（file/copy）→ 完了待ち（同時に進めている件どうしで、同じころに取る一覧は1回の取得を分け合う）
3. 保存前になかった、名前とサイズが一致するファイルを「自分が作ったコピー」とみなす
4. JD2に渡しておく数に空きがあれば、ダウンロードURLを発行してJD2へ渡す（空きがなければ、保存したまま空きを待つ）（CDNがファイルを `application/xml` などページの形式で返すことがあるので、`directhttp://` を付けてファイルとして扱わせる。URLにファイル名が入っていないので、リンクグラバーで名前を付けてからダウンロード一覧へ移す）
5. すぐにゴミ箱へ移して完全削除（削除に5回失敗したら、コピーは残したままダウンロードを見届ける。保存前からあったファイルは消さない。設定「残ったファイルを片付ける」をオンにしたときだけ、処理の合間にまとめて消す）。URLは削除後も使える
6. JD2での完了を見届けたら「完了」。JD2があきらめたとき、または受け取った量がファイルのサイズに足りないまま完了にされたときは、落としかけのファイルごとJD2の一覧から消し、新しいURLで再試行（最大3回）。受け取った量は、CDNが実際に配っている大きさ（URLの最後の段）と比べる。一時的な通信エラーはJD2が自分でやり直す。JD2で動いているのに10分進まない件は、いったん止めて動かし直す（全部受け取ったのに仕上げに進まず「開始中...」で止まることがある）。それでも進まなければ再試行する。JD2で無効にした・スキップした件は失敗にせず、メモを付けて待つ（JD2で有効に戻すと続く）。JD2の一覧から1分以上消えたままの件は、完了後に片付けられたとみなして「完了」にする

- 「開始」を押したときにJD2につながらなければ、始めずに理由を出す（ポップアップでは、JD2につながらない間は上に赤い帯で出る）
- 処理中にJD2につながらなくなったとき（3分以上。ダウンロード中の件しか残っていないときも）・Linkexのログインが切れたときは、件ごとの失敗に数えず全体を一時停止して通知する。このときの札は赤い「止まりました」になり、理由と対処を省略せずに出す
- Linkexが一時的に応えないとき（ネットが切れた・速度制限・サーバーの不調）は、読み取りだけ少し待って呼び直し、それでもだめなら件ごとの失敗に数えずに待つ。10分以上続いたら全体を一時停止して通知する（保存の頼み直しは、二重に保存しないよう速度制限で断られたときだけ）
- ダウンロード中の件がどれも15分以上進まなければ、通知で知らせる（JD2が「ファイルがあります」の確認を待っているなど）
- キューは拡張機能内に保存される。Edgeを閉じても続きから再開でき、Service Workerは1分ごとに起きて処理を続ける
- 何が起きたかは専用ページの「処理ログ」に残る（最新300件）

## しくみ

- **Service Worker**（`src/background/`）が全体の指示役。タブの中ではタイマーを回さないので、タブが裏に回っても止まらない
  - `engine.ts`：全体の指示役（次の件を選んで担当を付ける・失敗の数え方・全体の一時停止）
  - `engine-steps.ts`：1件ごとの段階（保存せずに取る / 保存 → コピー探し → URL → JD2 → 完全削除）
  - `jd-monitor.ts`：JD2での完了の見届け（完了・失敗・進まない件）
  - `engine-runtime.ts`：上の3つで分け合う実行中の状態（「開始」で消すもの）
  - `enqueue.ts`：共有の中身を読んでキューに追加
  - `linkex-tab.ts` / `linkex-bridge.ts`：Linkexの固定タブで、ページ内の通信部品を `import()` で取り出してAPIを呼ぶ。署名やログイン情報はページ自身が付ける
  - `jd2.ts`：JD2のローカルAPI
  - `origin-rule.ts`：JD2は Origin ヘッダーの付いたリクエストを断るので、この拡張機能からJD2へのリクエストだけ Origin を外す
- **専用ページ**（`dashboard.html`）とポップアップ（`popup.html`）
- **共有ページのパネル**（`src/content/share-page.ts`）：Shadow DOM の中に描くので、Linkexの画面を崩さない

## おまけ：拡張子の直し方

拡張子が消えて画像か動画かわからなくなったファイルは、`scripts/fix-extensions.ps1` で中身から判定して直せる。使い方は [docs/fix-extensions.md](docs/fix-extensions.md)。
