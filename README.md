# Linkex JD2

<img src="public/icons/icon-128.png" alt="" width="64" height="64" align="right" />

[Linkex](https://www.linkex.io/) の共有ファイルを、[JDownloader 2](https://jdownloader.org/)（JD2）でまとめて落とすEdge拡張機能です。共有リンクを登録しておけば、共有からダウンロードURLを発行してJD2に渡し、完了まで見届けます（直接取れないファイルは、自分のストレージに保存 → JD2でダウンロード → 完全削除、の流れで取ります）。

> v1 までは「Linkex Motrix」として、Motrix（aria2 RPC）へ渡していました。v2 で JD2 専用に変えています。Motrix に渡し済みだった件は、更新したときに「完了（Motrix版で渡した分）」として扱います（Motrix の中では最後まで続きます）。

> [!IMPORTANT]
> これはLinkex（LINKINFLU PTE. LTD.）の公式ツールではなく、関係もありません。個人利用の範囲で、Linkexの利用規約を守って使ってください。Linkex側の仕様が変わると動かなくなることがあります。利用は自己責任でお願いします。

## 必要なもの

- Microsoft Edge（Chromium版。Chromeでもおそらく動きますが未確認です）
- [JDownloader 2](https://jdownloader.org/)。「設定 → 詳細設定」で `RemoteAPI: Deprecated Api Enabled` をオンにして再起動しておきます（この拡張機能は 127.0.0.1:3128 のローカルAPIで追加・完了確認・速度表示をします。このAPIはこのPCの中からしか使えず、パスワードはありません）
- Linkexのアカウント（共有ファイルは自分のストレージに保存しないと落とせないため、ログインが必要です）
- ビルドする場合は Node.js 22.18 以上（テストが `.ts` をそのまま Node で動かすためです。`package.json` の `engines` にも書いてあります）

## インストール

### ビルド済みのものを使う（かんたん）

1. [Releases](https://github.com/Hoyomaru/linkex-jd2/releases/latest) から `linkex-jd2-vX.Y.Z.zip` をダウンロードし、好きな場所に展開します（このフォルダは消さずに置いておきます）
2. `edge://extensions` を開き、左下の「開発者モード」をオンにします
3. 「展開して読み込み」で、展開したフォルダ（`manifest.json` が入っているフォルダ）を選びます

### 自分でビルドする

```
npm install
npm run build
```

`dist/` に拡張機能ができるので、上の手順3で `dist` フォルダを選びます。

### 更新

フォルダの中身を新しい版に入れ替えてから、拡張機能の一覧で「再読み込み」を押します。キューや設定は残ります。

## 使い方

1. ツールバーのアイコン →「専用ページを開く」
2. 設定にJD2の接続先（ふつうは初期値のまま）と保存先を入れて「保存」→「接続テスト」
3. キューに共有リンクを登録します（どの方法でもかまいません）
   - 専用ページの「キュー」欄に共有URLを1行に1つずつ貼って「キューに追加」
   - Linkexの共有ページ右下のパネルで「全部キューに追加」または「選んで追加」（「選んで追加」は検索欄でファイル名・フォルダ名から、札で種類（動画・画像・音声・圧縮・その他。名前の拡張子で分けます）から、右の欄で大きさから絞り込めます。絞り込み中は表示中のファイルだけが追加の対象です。キューに入っているファイル・同じ中身が別の共有でキューに入っているファイル・同じ中身をダウンロード済みのファイルには印が付き、選べません）
   - ポップアップに貼り付けるか、「このページのリンクを集める」で今のページの共有リンクをまとめて拾う
   - Linkexのリンクを右クリック →「Linkex JD2 のキューに追加」（文字を選んで右クリックすると、その中のリンクを全部追加します）
4. 「開始」を押します。次のときは、追加すると自動で始まります
   - ポップアップ・専用ページ・共有ページのパネルから追加したとき：その画面の「追加したら開始する」がオン（初期値）
   - 右クリックで追加したとき：設定の「右クリックで追加したらすぐ開始」がオン（初期値）
5. 急ぎの共有があれば、専用ページのキューでその共有の「先に落とす」を押します。その共有の待ちの件が、ほかの共有より先に始まります（処理中の件はそのまま続きます。後から押した共有ほど先です）。「優先を外す」でキューに入った順に戻ります

ポップアップと専用ページには「見積もり」として、これから落とす合計サイズと、転送量の残りで足りるか（足りなければ上限ごとに止まりながら何日かかるか）が出ます。アカウントを切り替えて使うときは、切り替えに使うアカウント全部の残りの合計で見積もります（ほかのアカウントの残りは、最後に確かめた値です）。

転送量の残りは、新しい件を始める前に確かめます（1分に1回まで。その間は、残りから始めた件のサイズを引いて見込みます）。尽きていれば、別のアカウントに切り替えるか、戻るまで待ちます。前もっての確認をすり抜けても、LinkexがURLを断った時点で尽きたとみなします（件の失敗には数えず、保存済みのコピーもそのまま置いておきます）。共有ページの「選んで追加」でも、共有全体のサイズが分かります。

ツールバーのアイコンには残りの件数が出ます（失敗があれば赤）。すべて終わったときや、JD2につながらない・Linkexのログインが切れたなどで止まったときは、Windowsの通知で知らせます。キューの途中でも、共有1つ分が終わったら（完了・省略・失敗のどれかになったら）知らせます。

Linkexにはログインしておいてください。LinkexのAPIは、拡張機能の画面に出ない裏のページにLinkexのドライブを埋め込んで呼ぶので、タブは増えません。埋め込みが使えないとき（ログインが切れているときなど）だけ、Linkexのドライブが固定タブで自動的に開きます。

### 設定

| 項目 | 初期値 | 内容 |
|---|---|---|
| JD2の接続先 | `http://127.0.0.1:3128` | JD2のローカルAPI（Deprecated Api） |
| 基準フォルダ | 空（JD2の既定） | この下に `共有名\共有内のフォルダ` を作ります。共有の中身がフォルダ1つだけなら、共有名の段を飛ばしてそのフォルダから作ります |
| APIを呼ぶ間隔 | 300ミリ秒 | 一時的な速度制限を避けるためです |
| JD2に渡しておく数 | 3（1〜16） | ダウンロードURLには期限があるので、JD2の中で長く待たせないよう、渡すのはこの数までにします。実際に同時に落とす数はJD2の設定（全体の同時ダウンロード数・同じホストからの同時ダウンロード数）に従います。Linkexのファイルはすべて同じCDNから来るので、JD2の「同じホストからの同時ダウンロード数」が1だと1件ずつになります（「接続テスト」でJD2の今の設定が出ます） |
| 強制ダウンロード開始 | オフ | オンにすると、JD2に渡した件をJD2の「強制ダウンロード開始」にします。JD2の同時ダウンロード数・同じホストからの数の設定を超えて、「JD2に渡しておく数」まで同時に落とします。JD2をほかの用途と共用していて、JD2の設定は変えずにこちらだけ増やしたいとき向けです。強制で動いている分もJD2の同時数に数えられるので、その間はほかの用途の分が待たされることがあります |
| 同時に処理する数 | 3（1〜6） | Linkex側の処理を同時に進める数です（1にすると1件ずつ）。LinkexのAPIを同時に呼ぶ数の上限も兼ねます。保存せずに取るときは、URLの発行を同時に進める数になります。保存してから取るときは保存〜削除を同時に進める数で、保存中のコピーの合計は5GBと空き容量の小さいほうまでです。同じ名前のファイルは同時に保存しません |
| 保存せずにダウンロード | オン | 共有のファイルを自分のストレージに保存せず、共有から直接ダウンロードURLを発行してJD2へ渡します（Linkexへの呼び出しが1件あたり1回で済み、容量も使いません）。直接取れなかった件だけ、下の「処理の流れ」のとおり保存してから取ります |
| 先に保存しておく数 | 1（0〜3） | 保存してから取る件にだけ使います（「保存せずにダウンロード」がオンなら、直接取れなかった件だけが対象）。JD2に渡しておく数が埋まっている間に、次の件の保存まで済ませておく数（先読み）です。JD2に空きができたら、すぐURLを発行して渡します。URLは渡す直前に発行するので期限は気にしなくてかまいません。0にすると、空きができてから保存を始めます |
| 残ったファイルを片付ける | オフ | オンにすると、Linkex側で処理中の件がないとき（10分に1回まで、容量が足りないと言われたらすぐ）に、自分のストレージのルートとゴミ箱に残ったファイルを完全削除します。時間切れの後に遅れてできたコピーや、削除の途中で止まったコピーで容量が埋まるのを防ぎます。**保存前からあったファイルも消えます**（フォルダとキューの件のコピーは消しません）。アカウントを切り替えて使うときは、切り替えたアカウントごとに（切り替えた直後にも）消します。自分のファイルを置いていないときだけオンにしてください |
| 拡張子を付ける | オン | 名前に拡張子が無い（または `video.2024` のように見慣れない）ファイルは、JD2に渡す前にダウンロードURLの先頭512バイトだけ取って中身の種類を調べ、拡張子を付けた名前で保存します。判定の決まりは `scripts/fix-extensions.ps1` と同じです。知っている拡張子が中身と違っている場合は変えません（落とした後にスクリプトで直せます） |
| 通知を出す | オン | すべて終わったとき・止まったとき |
| 共有ごとに通知 | オン | キューの途中でも、共有1つ分が終わったら知らせます（「通知を出す」がオンのときだけ） |
| 右クリックで追加したらすぐ開始 | オン | 右クリックメニューから追加したときの動き |
| 転送量が尽きたら別のアカウントに切り替える | オン | 専用ページの設定にある「Linkex → アカウント」で切り替えます。くわしくは下の「アカウントの切り替え」。アカウントが1つなら何も変わりません |

保存先にもう同じ名前のファイルがあると、JD2の初期設定では上書きするか聞いてきて、そのダウンロードは答えるまで止まります。留守中に回すなら、JD2の「設定 → 一般 → ファイルが既に存在する場合」を、聞かずに済む動きにしておきます。おすすめは「名前を変える」です。「スキップ」にすると、スキップされた件はJD2で無効・スキップにされた件として、キューに「ダウンロード中」のまま残り、メモを付けて待ちます（JD2で有効に戻すか、キューから外してください）。

JD2の「設定 → 一般 → 完了したダウンロードを削除」は、「しない」か「終了時」にしておくのがおすすめです。「すぐ」（またはパッケージ完了時）だと、完了した件がJD2の一覧から消えてしまい、受け取った量が足りているかを確かめられません（一覧から消えたことで完了とみなします）。「接続テスト」でこの設定のときは注意が出ます。

## アカウントの切り替え

転送量の上限に達すると、LinkexはダウンロードURLを出さなくなります。運営からは、アカウントを複数作ってそれぞれの転送量を使ってよいと返事をもらっています。Linkex Web版に複数のアカウントを覚えさせておくと、転送量が尽きたときに別のアカウントへ自動で切り替えて続けます。

- **足し方**：Linkex で右上のアイコン →「ログアウト」→ 別のアカウントでログインすると、Web版の「アカウントを切り替え」に足されます（ログアウトしても、前のアカウントのログイン情報は残ります。覚えておけるのは10アカウントまで）。拡張機能が使う Linkex（拡張機能を入れたブラウザ）で行ってください。足したアカウントは、専用ページの「設定 → Linkex → アカウント」に出ます
- **拡張機能はログイン情報を持ちません**。ログイン情報は Web版の保存場所に置いたままで、拡張機能は Linkex のページの中で、Web版と同じ書き換えをするだけです（使うアカウントの指定と、今使っていないアカウントのログイン情報の更新）。トークンは拡張機能に渡さず、保存もしません。開いている Linkex のタブも一緒に切り替わります
- **切り替えの流れ**：転送量が尽きたら新しい件を止め、保存してから取る件のコピーは消して待機中に戻してから（転送量は使いません）、次のアカウントに切り替えて続けます。JD2で落としている最中の件は、そのまま落とし続けます（出したURLは切り替えた後も使えます）。片付けが10分で終わらなければ、そのまま切り替えます（前のアカウントにコピーが残ることがあります）
- **選ぶ順番**：切り替えに使うアカウントのうち、期限のいちばん近いものから使います。転送量が尽きたアカウントは、戻ったと分かるまで（確かめられなければ、尽きてから24時間）使いません
- **転送量の確認**：転送量は24時間で一度に戻るのではなく、直近24時間に使った分として少しずつ戻ります。尽きたアカウントは、1時間ごとに切り替えずに転送量を確かめ、戻っていればすぐ使えるようにします（全部尽きて待っているときは、そのアカウントに切り替えて再開します）
- **期限**：Web版は、ログイン情報が更新されてから20日たったアカウントを一覧から消します。今使っていないアカウントは、期限まで11日を切ったら、拡張機能が1時間ごとの見回りで、切り替えずにその場でログイン情報を更新します（Web版がトークンを更新するときと同じ通信と書き戻し方。期限が20日延びます。今使っているアカウントは Web版が自分で更新します）。Edge を開いていれば、処理を動かしていなくても見回ります。更新できなかったとき・一覧から消えたときは、専用ページの上に知らせが出ます（ログインし直すと延びます）
- **全部尽きたら**：尽きた時刻から24時間たったアカウントから順に試します。まだ尽きていれば1時間後にもう一度試します。待っている間は「◯時◯分ごろに △△ で再開」と出ます
- 自分で Web版のアカウントを切り替えたときは、そのアカウントで続けます
- 切り替えに使いたくないアカウントは、一覧のチェックを外します

### 覚えさせたアカウントを別のPCに移す

Web版が覚えている全アカウントのログイン情報は、Edge の `https://www.linkex.io` の localStorage にある `linkex_user_cache_v1` という1つの値にまとめて入っています。これをコピーすれば、別のPCでもログインし直さずに同じアカウントの一覧が使えます（拡張機能はこの値を読むだけなので、拡張機能の側で設定することはありません）。

1. 今のPCの Edge で `https://www.linkex.io/drive/` を開き、F12 →「コンソール」で次を実行します。値がクリップボードにコピーされます
   ```js
   copy(localStorage.getItem('linkex_user_cache_v1'))
   ```
2. メモ帳などに貼って保存し、USBメモリなどで別のPCに移します
3. 別のPCの Edge で `https://www.linkex.io/drive/` を開き、コンソールで `localStorage.setItem('linkex_user_cache_v1', JSON.stringify(` と打ってから、手順2の中身をそのまま貼り、`))` で閉じて実行します。初めて貼るときは、Edge に「allow pasting」と打つよう求められることがあります
   ```js
   localStorage.setItem('linkex_user_cache_v1', JSON.stringify(ここに貼る))
   ```
4. ページを読み込み直します。右上のアイコン →「アカウントを切り替え」に、移したアカウントが出ていれば完了です

注意：

- **同じログイン情報を2台で同時に使わないでください**。ログイン情報を更新すると、Linkex が新しいトークンを返して古いほうが使えなくなることがあり、もう片方のPCでログインが切れるおそれがあります。移した後は元のPCでは使わないか、2台とも使い続けるならそれぞれのPCでログインし直してください
- 移したファイルは、全アカウントのパスワードと同じ扱いです。クラウドやチャットには置かず、移し終わったら消してください
- ログイン情報は、更新されてから20日で使えなくなります。古いコピーは使わず、移す直前に書き出してください

## 処理の流れ（1件ごと）

「保存せずにダウンロード」がオン（初期値）なら、同じ中身をダウンロード済みでないかを確かめた後、共有から直接ダウンロードURLを発行してJD2へ渡し、JD2での完了を見届けます（下の 4 と 6 だけ）。直接取れなかった件と、オフのときは次のとおりです。

1. 同じ中身をダウンロード済みなら飛ばします（ハッシュで判定します。「もう一度ダウンロード」で強制できます。記録は専用ページの設定にある「ダウンロード済みの記録」でまとめて消せます）
2. 保存前の自分のファイル一覧を記録 → 共有から保存（file/copy）→ 完了待ち（同時に進めている件どうしで、同じころに取る一覧は1回の取得を分け合います）
3. 保存前になかった、名前とサイズが一致するファイルを「自分が作ったコピー」とみなします
4. JD2に渡しておく数に空きがあれば、ダウンロードURLを発行してJD2へ渡します（空きがなければ、保存したまま空きを待ちます）（CDNがファイルを `application/xml` などページの形式で返すことがあるので、`directhttp://` を付けてファイルとして扱わせます。URLにファイル名が入っていないので、リンクグラバーで名前を付けてからダウンロード一覧へ移します。名前に拡張子が無ければ、渡す前に中身から拡張子を付けます）
5. すぐにゴミ箱へ移して完全削除します（削除に5回失敗したら、コピーは残したままダウンロードを見届けます。保存前からあったファイルは消しません。設定「残ったファイルを片付ける」をオンにしたときだけ、処理の合間にまとめて消します）。URLは削除後も使えます
6. JD2での完了を見届けたら「完了」です。JD2があきらめたとき、または受け取った量がファイルのサイズに足りないまま完了にされたときは、落としかけのファイルごとJD2の一覧から消し、新しいURLで再試行します（最大3回）。受け取った量は、CDNが実際に配っている大きさ（URLの最後の段）と比べます。一時的な通信エラーはJD2が自分でやり直します。JD2で動いているのに10分進まない件は、いったん止めて動かし直します（全部受け取ったのに仕上げに進まず「開始中...」で止まることがあります）。それでも進まなければ再試行します。JD2で無効にした・スキップした件は失敗にせず、メモを付けて待ちます（JD2で有効に戻すと続きます）。JD2の一覧から消えた件は、完了後に片付けられたとみなして「完了」にします（JD2が1分以上続けて応答していれば数秒で、JD2の起動直後やつながらなかった直後は、一覧が一時的に空で返ることがあるので1分消えたままなら）

- 「開始」を押したときにJD2につながらなければ、始めずに理由を出します（ポップアップでは、JD2につながらない間は上に赤い帯で出ます）
- 処理中にJD2につながらなくなったとき（3分以上。ダウンロード中の件しか残っていないときも）・Linkexのログインが切れたときは、件ごとの失敗に数えず全体を一時停止して通知します。このときの札は赤い「止まりました」になり、理由と対処を省略せずに出します
- Linkexが一時的に応えないとき（ネットが切れた・速度制限・サーバーの不調）は、読み取りだけ少し待って呼び直し、それでもだめなら件ごとの失敗に数えずに待ちます。10分以上続いたら全体を一時停止して通知します（保存の頼み直しは、二重に保存しないよう速度制限で断られたときだけです）
- ダウンロード中の件がどれも15分以上進まなければ、通知で知らせます（JD2が「ファイルがあります」の確認を待っているなど）
- キューは拡張機能内に保存されます。Edgeを閉じても続きから再開でき、Service Workerは1分ごとに起きて処理を続けます
- 何が起きたかは専用ページの「処理ログ」に残ります（最新300件）

## おまけ：拡張子の直し方

拡張子が消えて画像か動画かわからなくなったファイルは、`scripts/fix-extensions.ps1` で中身から判定して直せます。使い方は [docs/fix-extensions.md](docs/fix-extensions.md) にあります。

## 開発メモ

### ビルドとテスト

- `npm run build` は型チェック（`tsc --noEmit`）もしてからビルドします。`content.js` だけは別の設定 `vite.content.config.ts` で1ファイルにまとめてビルドします
- 型チェックだけなら `npm run typecheck`（テストのコードも `tsconfig.test.json` で型チェックします）、テストは `npm test`
- ビルドし直したら、拡張機能の一覧で「再読み込み」を押し、開いている共有ページも再読み込みします。`npm run watch` にしておくと、ソースを変えるたびに `dist` が作り直されます（このときも「再読み込み」は必要です）

### しくみ

- **Service Worker**（`src/background/`）が全体の指示役です。タブの中ではタイマーを回さないので、タブが裏に回っても止まりません
  - `engine.ts`：全体の指示役（次の件を選んで担当を付ける・失敗の数え方・全体の一時停止）
  - `engine-steps.ts`：1件ごとの段階（保存せずに取る / 保存 → コピー探し → URL → JD2 → 完全削除）
  - `jd-monitor.ts`：JD2での完了の見届け（完了・失敗・進まない件）
  - `engine-runtime.ts`：上の3つで分け合う実行中の状態（「開始」で消すもの）
  - `enqueue.ts`：共有の中身を読んでキューに追加
  - `linkex-bridge.ts`：Linkexのドライブのページ内で、ページの通信部品を `import()` で取り出してAPIを呼びます。署名やログイン情報はページ自身が付けます
  - `linkex-frame.ts`：拡張機能の裏のページ（`offscreen.html`）にドライブを iframe で埋め込み、その中（`src/content/drive-frame.ts`）で上の関数を呼びます。タブのように凍結されません
  - `linkex-tab.ts`：Linkexを呼ぶ入口。埋め込みが使えないときは、ドライブを固定タブで開いてその中で呼びます
  - `linkex-accounts.ts`：Web版に覚えさせてあるアカウントの読み取りと切り替え、アカウントごとの記録（判定は `src/shared/accounts.ts`）
  - `account-maintenance.ts`：1時間ごとの見回り。今使っていないアカウントの期限を延ばし、尽きたアカウントの転送量を確かめます（ページの中の処理は `src/content/account-ops.ts`。トークンはページから出しません）
  - `jd2.ts`：JD2のローカルAPI
  - `origin-rule.ts`：JD2は Origin ヘッダーの付いたリクエストを断るので、この拡張機能からJD2へのリクエストだけ Origin を外します
- **専用ページ**（`dashboard.html`）とポップアップ（`popup.html`）
- **共有ページのパネル**（`src/content/share-page.ts`）：Shadow DOM の中に描くので、Linkexの画面を崩しません
